# 🏁 維基百科競速 · 線上對戰

和朋友一對一（或最多 8 人派對）比賽：從起點條目出發，**只能點擊條目內的連結**，誰先抵達終點條目誰就獲勝。

## 玩法

1. 輸入暱稱，按「建立房間」，取得 5 碼房間代碼。
2. 按「複製邀請連結」傳給朋友（或讓朋友輸入代碼加入）。
3. 房主設定起點／終點條目（可輸入、可按 🎲 隨機，留空開始時也會自動隨機）、語言版本、時間限制。
4. 朋友按「準備」，房主按「開始比賽」，倒數 3 秒後同時開始。
5. 比賽中可以看到對手的步數與（可選）目前所在條目；先抵達終點的人獲勝，雙方都抵達則比用時。

## 派對模式

- 首頁選「2–8 人 派對模式」再建立房間，最多 8 人一起比同一個題目。
- 所有玩家按「準備」後，房主就能開始。
- 依抵達順序與用時排名（比步數則依步數）。房主可以設定「最後衝刺」：第一個人抵達後其他人只剩 30 秒到 3 分鐘，或不限時間比到最後；投降或時間到就沒有名次。
- 先抵達的人可以看即時排行榜等其他人，結束後每個人的路線都能展開查看。

## 其他功能

- **快速表情**：房間、比賽中、結算畫面都能丟表情或快捷語，會飄過所有人的畫面。
- **房內聊天**：房間與結算畫面共用聊天室，重新連線的人也看得到最近的訊息。
- **斷線重連**：玩家斷線後會自動重連；比賽中保留 60 秒、房間裡保留 15 秒。重新整理網頁也會自動回到原本的房間與進度。
- **轉移房主**：房主可以把房間交給其他玩家；房主離開時房間會自動交給下一位，不會解散。
- **道具賽**：每 40 秒自動發一個道具（迷霧、天旋地轉、冰凍、香蕉皮、蝸牛、閃電、護盾、水晶球），離終點越遠的人拿到越強的道具。
- **自選背景音樂**：大廳和比賽音樂各自選內建曲目（輕快鋼琴、8-bit 冒險、Lo-fi 放鬆、緊張節奏），或用手機裡自己的音樂檔。
- **分享戰績圖**：結算後產生一張 1080×1350 的戰績圖，可直接分享或存到相簿。

## 技術說明

- **純靜態網站**，不需要後端：`index.html`、`style.css`、`app.js`、`wiki.js`、`net.js`、`fx.js`（背景音樂、音效、觸覺回饋與特效）、`topics.js`（超過一萬個隨機條目）、`zh.js`（簡轉繁）、`share.js`（戰績圖）。
- 線上對戰使用 [PeerJS](https://peerjs.com/)（WebRTC 點對點連線），透過 PeerJS 免費的公開配對伺服器建立連線。房主當中繼站，每位玩家只連到房主。
- 條目內容即時從維基百科 API 讀取，中文版使用 `zh-tw` 台灣正體轉換；也支援英文維基。

- 隨機條目從內建的 10,000+ 題庫抽選（已排除艱澀條目），抽到時會向維基百科確認條目存在、不是消歧義頁，而且近 30 天瀏覽量夠高；英文模式透過跨語言連結轉換。
- 背景音樂與音效是由 `audio/render.py` 離線合成的 mp3，用瀏覽器原生的 `<audio>` 播放（不在手機上即時合成，避免 iPhone 雜音）。

## 本機執行

```bash
python3 -m http.server 8000
# 開啟 http://localhost:8000
```

（要用 http server 開，不能直接雙擊 html 檔，因為使用了 ES modules。）

## 部署到 GitHub Pages

1. 把程式合併到 `main` 分支。
2. 到 GitHub repo 的 **Settings → Pages**，Source 選 **GitHub Actions**。
3. 之後每次推送到 `main` 都會自動部署，網址為 `https://<你的帳號>.github.io/<repo 名稱>/`。

也可以部署到 Firebase Hosting、Netlify、Vercel 等任何靜態網站服務。

## 線上人數（選用）

首頁可以顯示「🟢 N 人在線上」。這需要一個免費的 Firebase 專案（遊戲本身不需要後端，只有這個計數需要）。不設定的話，首頁就不會出現這塊，其他功能一切正常。

設定步驟：
1. 用 Google 帳號登入 <https://console.firebase.google.com/>，點「建立專案」，名稱隨意，不用開 Google Analytics。
2. 左側選 **Build → Realtime Database → 建立資料庫**，位置選「新加坡（asia-southeast1）」之類離台灣近的，規則先選 **測試模式（test mode）**。
3. 建好後，到 Realtime Database 的 **規則（Rules）** 分頁，貼上這段後按發布（這幾個路徑分別給線上人數、房間概況、歷史統計、全站公告、後台指令用）：
   ```json
   {
     "rules": {
       "online": { ".read": true, ".write": true },
       "rooms": { ".read": true, ".write": true },
       "stats": { ".read": true, ".write": true },
       "broadcast": { ".read": true, ".write": true },
       "control": { ".read": true, ".write": true }
     }
   }
   ```
4. 回到專案首頁，點 **</> 網頁**，註冊一個 App，Firebase 會給你一段 `const firebaseConfig = { ... }`。
5. 打開本專案的 `firebase-config.js`，把那段貼進去，改成：
   ```js
   window.WIKIRACE_FIREBASE = {
     apiKey: '...', authDomain: '...', databaseURL: 'https://...firebaseio.com',
     projectId: '...', appId: '...',
   };
   ```
   **一定要有 `databaseURL`**（在 Realtime Database 頁面上方看得到）。
6. 推送到 `main` 重新部署即可。

這個計數只記「現在有幾個人打開網站」的總數，不會記下是誰、也看不到任何人的畫面。免費額度對朋友間的使用綽綽有餘。

## 製作者後台（選用）

設定好上面的 Firebase 後，`admin.html` 是一個給製作者看的營運儀表板，打開 `https://<你的網址>/admin.html` 並輸入密碼即可（密碼寫在 `admin.html` 最上面的 `ADMIN_PASS`，想改就改那一行）。後台可以看到：

- **即時概況**：現在有幾間房間、幾個人在玩、幾個人在線上、史上同時在線尖峰。
- **歷史統計**：今日／本週／全部的對局數、玩家人次、完成率、再玩率、平均一局時間、平均步數、各模式分布、最常「沒人抵達」的題目。
- **正在遊玩的房間**：每間房的代碼、房主、模式、題目與每位玩家的步數進度（可依最新／人多／開最久排序、只看比賽中）。必要時可以**關閉房間**或**踢出某位玩家**。
- **全站公告**：打一句話推到所有正在玩的人畫面上（玩家可以自己關掉）。

後台只看得到房間層級的概況，**看不到任何人的實際畫面、也不會鏡像誰在看哪個條目**。遊戲首頁也有一行說明，讓玩家知道會收集哪些匿名的房間資訊。
